# 修补点位清单

三个音频栈共 29 处、153 字节的代码改动，逐点记录在这里。所有数据都能用
[`tools/compare-drivers.py`](../tools/compare-drivers.py) 重新生成：

```bat
python tools/compare-drivers.py reference\originals\csaudiosstavs drivers\audio\csaudiosstavs
```

比对基线是 [`reference/originals/`](../reference/originals/) 里的官方原包（未改动），
右侧是安装器实际投放的 `drivers/audio/` 版本。

| 驱动栈 | 补丁点 | 改动字节 | `.sys` 体积 |
|---|---|---|---|
| `csaudiosstavs`（AVS，Skylake 世代） | 5 | 25 B | 106 672 → 119 048 B |
| `csaudiointcsof`（SOF，Gemini Lake 及更新） | 12 | 64 B | 160 480 → 166 664 B |
| `csaudioamdsof`（AMD SOF） | 12 | 64 B | 116 856 → 123 144 B |

体积增加来自签名块（换了证书链与时间戳），代码段没有增长。

---

## 一、两类点位

29 处全部落在 `.text`，只有两种形态。

### A 类：错误分支直接返回

```asm
mov   eax, 0xC000026A     ; 4 字节，B8/BB + imm32
jmp   0x140004970         ; 跳到函数收尾
```

授权校验失败时走的路径，把失败码写进返回值再跳走。把立即数改成 0 即可，指令长度不变，
后续跳转偏移不受影响。

### B 类：三元表达式收尾

```asm
sbb   ebx, ebx            ; ebx = 0 或 -1，取决于上一处比较的 CF
not   ebx                 ; 取反：0 ↔ -1
and   ebx, 0xC000026A     ; 全 1 时得到 0xC000026A，否则得到 0
jmp   ...
```

这是 MSVC 给 `return cond ? STATUS_X : STATUS_SUCCESS;` 生成的收尾序列：条件成立返回失败码，
否则返回 0。`and` 的立即数改成 0 后，无论条件如何结果都是 0，等价于恒定成功。

`and ebx, 0xC000026A` 是 6 字节（`81 E3` + imm32），改成 `83 E3 00`（`and ebx, 0`）只有
3 字节，多出的 3 字节用 `nop` 填平，保持后续指令地址不变。`and eax` 同理（`25` + imm32 →
`83 E0 00` + 2 个 `nop`）。

原代码里紧跟其后的 `mov ebx, 0xC0000017`（`STATUS_NO_MEMORY`）没有被改动 —— 那是真正的
内存不足分支，与授权无关。

## 二、AVS：`csaudiosstavs`，5 处 / 25 字节

| # | 文件偏移 | 虚拟地址 | 原始字节 | 修补字节 | 原始指令 | 修补后指令 |
|---|---|---|---|---|---|---|
| 1 | `0x003BCB` | `0x1400047CB` | `6A 02 00 C0` | `00 00 00 00` | `mov eax, 0xc000026a` | `mov eax, 0` |
| 2 | `0x003C66` | `0x140004866` | `6A 02 00 C0` | `00 00 00 00` | `mov ebx, 0xc000026a` | `mov ebx, 0` |
| 3 | `0x0042D9` | `0x140004ED9` | `25 6A 02 00 C0` | `83 E0 00 90 90` | `and eax, 0xc000026a` | `and eax, 0` |
| 4 | `0x004A83` | `0x140005683` | `81 E3 6A 02 00 C0` | `83 E3 00 90 90 90` | `and ebx, 0xc000026a` | `and ebx, 0` |
| 5 | `0x004DE0` | `0x1400059E0` | `81 E3 6A 02 00 C0` | `83 E3 00 90 90 90` | `and ebx, 0xc000026a` | `and ebx, 0` |

第 1、2 处的偏移指向立即数本身，指令起始比表中偏移小 1 字节（`B8` / `BB`）。
第 3 处是函数尾部（`and eax, ...` 后直接 `mov rsp, r11; pop rbp; ret`）。

第 1 处的上下文：

```asm
1400047B5  call   0x1400077e8        ; 授权校验
1400047BA  test   eax, eax
1400047BC  jns    0x1400047d4        ; 成功 → 继续初始化 ADSP
1400047BE  lea    rcx, [rip+0x622b]  ; "AVS: License not found..."
1400047C5  call   0x1400091a0        ; 打日志
1400047CA  mov    eax, 0xC000026A    ; ← 补丁 1
1400047CF  jmp    0x140004970
```

这个包有 4 处没有改成 0，而是改成 `0x0A`（十进制 10）：第 1、3、4、5 处。

```asm
mov   eax, 0x0A          ; 原 mov eax, 0xC000026A
and   ebx, 0x0A          ; 原 and ebx, 0xC000026A
```

NTSTATUS 里负值表示失败，`0x0A` 是正数，与 0 一样会被判为成功。推测改动者留了一个非零
标记，让某些「status 非零就记日志」的分支仍然留下痕迹。功能上与改成 0 等价。

## 五、没有改动的部分

| 对象 | 状态 |
|---|---|
| `.inf`（含 HWID 表、`DeviceDesc`、服务安装段、`CatalogFile`） | 与官方包逐字节相同 |
| DSP 固件（`dsp_*.bin`、`sof-*.ri`） | 未改动 |
| `CsAudioCallbackAPI` 回调注册 | 保留，`ssm4567` 依赖它注册 Speaker 端点 |
| 官方包里的 `cacert.exe`、`dpinst.exe`、`.sys.i64` | 安装器不投放（工具与 32 位版本） |

改动只影响「校验失败时返回什么」，不改变音频通路本身的初始化序列。

## 六、换版本时怎么重新定位

**不要照抄偏移。** 换一个编译版本，指令地址全变。可用的做法：

1. 拿官方原包和自己的补丁包各一份，跑 `tools/compare-drivers.py`，它会列出所有落在
   `.text` 内的差异块并给出前后反汇编。这是最稳的办法。
2. 只有原包时，按字节特征搜索，再人工确认上下文：

```
6A 02 00 C0            ; mov reg, 0xC000026A 的立即数（前面应是 B8..BF）
81 E3 6A 02 00 C0      ; and ebx, 0xC000026A
25 6A 02 00 C0         ; and eax, 0xC000026A
```

3. 命中后检查三件事：是否落在 `.text`；前面是否存在 `sbb/not` 或 `test/jns` 这类条件序列；
   改完是否仍是等长或已被 `nop` 补齐。

改完 `.sys` 的字节，原来的 catalog 就失效了，必须重新生成并签名 —— 流程见
[FakeSign](https://github.com/PIKACHUIM/FakeSign)。
